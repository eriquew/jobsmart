Sprint 0 Foundation — project setup, schema, base connector 1 week · 13 pts ▾
Goal: repo running, DB up, one connector working end-to-end Definition of done: Job Bank returns data and saves to PostgreSQL
US-01 As a developer I want a GitHub repo with the MVC directory structure so that the project has a clean foundation from day one.
E5
2 pts
  • Repo created with model / controller / view / config / tests folders
  • .gitignore excludes .env, __pycache__, *.pyc, secrets.yaml
  • requirements.txt contains all dependencies pinned to version
  • Makefile has make init, make run, make test, make dashboard targets
  • README.md has project description and setup instructions
US-02 As a developer I want a PostgreSQL schema with the jobs table so that all sources store data in a unified structure.
E1
2 pts
  • schema.sql creates jobs table with all fields: id, source, title, company, location, salary_min, salary_max, description, url, date_posted, date_ingested, score_total, score_technical, score_seniority, score_industry, score_location, flag_french_required, status
  • Unique index on (title, company, location) for deduplication
  • make init runs schema.sql and creates the DB
  • db_connection.py returns a reusable psycopg2 connection
US-03 As a developer I want a Job dataclass and base connector abstract class so that all six connectors share the same interface.
E1
3 pts
  • Job dataclass has all schema fields with types and defaults
  • Job.validate() raises ValueError on missing required fields
  • BaseConnector defines abstract fetch() and normalize() methods
  • BaseConnector implements rate_limit() with configurable delay
  • BaseConnector implements retry() with exponential backoff
US-04 As Wilson I want the Job Bank Canada connector working so that I have a verified baseline of official Canadian job postings.
E1
3 pts
  • jobbank.py extends BaseConnector and implements fetch() and normalize()
  • Accepts keywords and location as parameters
  • Returns list of Job objects with all fields populated where available
  • Handles pagination — fetches up to configured max_results
  • Unit test with fixture passes without hitting the live API
US-05 As a developer I want a job repository with save and deduplicate so that duplicate listings across sources are not stored twice.
E1
3 pts
  • job_repository.save() uses INSERT ON CONFLICT DO NOTHING
  • deduplicator.py generates a hash from title + company + location (lowercased, stripped)
  • Running the same source twice does not create duplicate rows
  • job_repository.find_by_score() returns jobs ordered by score_total desc
Sprint 1 All six connectors + parallel pipeline 1 week · 18 pts ▾
Goal: all sources fetching and saving in one make run command Definition of done: 100+ real jobs in PostgreSQL from 6 sources
US-06 As Wilson I want Adzuna and Jooble connectors so that I have API-sourced coverage of the broader Canadian market.
E1
4 pts
  • adzuna.py and jooble.py each extend BaseConnector
  • API keys loaded from .env — never hardcoded
  • Both normalize salary fields to salary_min / salary_max integers where available
  • Both handle API rate limit responses with retry backoff
  • Unit tests with fixture data pass for both
US-07 As Wilson I want RemoteOK, LinkedIn, and Indeed connectors so that remote roles and the two largest job boards are included.
E1
5 pts
  • remoteok.py calls public JSON API — no key required
  • linkedin.py and indeed.py use jobspy with configurable search terms and location
  • All three normalize to the Job schema
  • Request rate limited — minimum 2s delay between calls to avoid blocking
  • Graceful fallback if jobspy returns empty — logs warning, does not crash pipeline
US-08 As Wilson I want a pipeline orchestrator that runs all six sources in parallel so that a full ingestion run completes in under 2 minutes.
E1
5 pts
  • pipeline.py uses concurrent.futures.ThreadPoolExecutor to run connectors in parallel
  • Each source runs independently — failure of one does not block others
  • Pipeline logs: source name, jobs fetched, jobs saved, jobs deduplicated, elapsed time
  • make run triggers pipeline.py with default keywords from settings.yaml
  • Full run of 6 sources completes in under 2 minutes on local machine
US-09 As a developer I want the pipeline to accept keyword and location arguments so that I can target specific roles and cities.
E1
2 pts
  • pipeline.py accepts --keywords and --location CLI arguments via argparse
  • Defaults loaded from settings.yaml if no arguments provided
  • Multiple keywords supported as comma-separated string
US-10 As a developer I want cross-source deduplication so that the same job appearing on LinkedIn and Indeed is stored once.
E1
2 pts
  • deduplicator checks existing DB records before insert using the hash key
  • Fuzzy match threshold configurable in settings.yaml (default 90% similarity)
  • Pipeline log reports deduplicated count per run
Sprint 2 NLP processing + scoring engine 1 week · 21 pts ▾
Goal: every job in DB has a fitness score against Wilson's profile Definition of done: score_total populated for all jobs, French flag working
US-11 As Wilson I want a profile.yaml where I define my skills, target titles, industries, and locations so that the scoring engine uses my actual profile.
E4
2 pts
  • profile.yaml has sections: target_titles, skills, industries, locations, seniority_keywords, exclusions, weights
  • weights section controls relative importance of each score dimension (must sum to 1.0)
  • exclusions list contains terms that automatically set score to 0 (e.g. "French required")
  • profile_loader.py validates YAML schema on load and raises clear error on missing fields
US-12 As Wilson I want the NLP processor to extract skills and flag French-required roles so that I can filter out roles I cannot apply to.
E2
5 pts
  • nlp_processor.py uses spaCy en_core_web_sm model
  • extract_skills() returns list of matched skills from a curated tech vocabulary
  • detect_french() sets flag_french_required=True if JD contains "French required", "bilingual", "français" or similar patterns
  • detect_seniority() returns: junior / mid / senior / manager / director
  • extract_salary() parses salary ranges from free text when not provided as structured fields
US-13 As Wilson I want a scoring engine that gives each job a fitness percentage against my profile so that I can prioritize which roles to pursue.
E2
8 pts
  • scoring_engine.py uses TF-IDF vectorization + cosine similarity between JD and profile skills corpus
  • score_technical: skill overlap between extracted JD skills and profile skills (0–100)
  • score_seniority: match between detected JD seniority and profile target seniority (0–100)
  • score_industry: keyword match between JD and profile industries (0–100)
  • score_location: exact + fuzzy match on city/province (0–100)
  • score_total: weighted average using profile.yaml weights
  • French-required roles get score_total capped at 40 unless French is in profile skills
  • Scores updated in DB after every pipeline run
US-14 As a developer I want the scoring engine to re-score all jobs when profile.yaml changes so that updating my profile immediately reflects in rankings.
E2
3 pts
  • make rescore command triggers re-scoring of all jobs in DB without re-fetching sources
  • Batch re-score processes 100 jobs at a time to avoid memory issues
  • Logs total jobs re-scored and elapsed time
US-15 As Wilson I want unit tests for the scoring engine with known inputs so that I can trust the fitness scores are calculated correctly.
E5
3 pts
  • test_scoring.py has at least 5 test cases with fixture JDs and known expected scores
  • Tests cover: perfect match, zero match, French flag cap, seniority mismatch, partial skill overlap
  • make test runs all tests and exits 0 on pass
Sprint 3 Streamlit dashboard — core view 1 week · 20 pts ▾
Goal: usable dashboard showing ranked jobs with filters and direct links Definition of done: Wilson can run make dashboard and find a job to apply to in under 5 minutes
US-16 As Wilson I want a ranked jobs table showing title, company, location, score, salary, source, and date so that I can scan all opportunities at a glance.
E3
5 pts
  • dashboard.py renders st.dataframe with columns: title, company, location, score_total (%), salary range, source, date_posted
  • Default sort: score_total descending
  • Score column shows colored badge: green ≥75, amber 50–74, red <50
  • French-required roles show 🇫🇷 flag indicator
  • Table is clickable — selecting a row navigates to job_detail page
US-17 As Wilson I want a filter sidebar so that I can narrow the table by minimum score, source, city, and date range.
E3
4 pts
  • filter_panel.py renders in st.sidebar with: score slider (0–100), source multiselect, location multiselect, date range picker, hide French-required toggle
  • Filters apply immediately without page reload
  • Filter state persists during the session
  • Job count updates dynamically as filters change
US-18 As Wilson I want a job detail page showing the full JD, score breakdown, and a direct apply link so that I can evaluate and act on a role without leaving the dashboard.
E3
5 pts
  • job_detail.py shows: full job description, score breakdown bar chart by dimension, extracted skills matched vs missing, salary, company, date posted
  • Direct link button opens original posting URL in new tab
  • Status buttons: Mark as Reviewed / Mark as Applied / Reject — updates DB status field
  • Back button returns to filtered dashboard without losing filter state
US-19 As Wilson I want a "Run pipeline now" button in the dashboard so that I can trigger a fresh ingestion without opening a terminal.
E3
3 pts
  • Sidebar shows "Run pipeline" button with last run timestamp
  • Button triggers pipeline.py via subprocess and shows a spinner while running
  • On completion shows: new jobs added, duplicates skipped, sources that failed
  • Table refreshes automatically after pipeline completes
US-20 As Wilson I want a summary header showing total jobs, new today, average score, and applied count so that I can see pipeline health at a glance.
E3
3 pts
  • Header row shows 4 st.metric cards: Total jobs, New today, Avg score, Applied
  • Metrics update in real time as filters change
  • New today counts jobs with date_ingested = today
